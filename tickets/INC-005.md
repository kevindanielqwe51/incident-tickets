\# Ticket 05: Private Endpoint DNS Resolution and HTTPS Connectivity Failure



\*\*Area:\*\* Networking / Azure Storage | \*\*Services:\*\* Azure Private Endpoint, Private DNS Zone, Storage Account, NSG, Network Watcher



\## Symptom



A VM was unable to resolve the Storage Account Private Endpoint FQDN using `nslookup`. Additionally, HTTPS requests using a SAS URL to retrieve a blob from the Storage Account failed with a connection timeout.



!\[Initial DNS and HTTPS connectivity failure](screenshots/01-initial-dns-and-https-connectivity-failure.png)



\## Diagnosis



1\. Tested DNS resolution using `nslookup` → The Private Endpoint FQDN could not be resolved.

2\. Tested HTTPS connectivity using `curl -i` with a SAS URL → Connection timed out.

3\. Inspected the Private DNS Zone → The Private Endpoint DNS record set was missing.



!\[Missing DNS record set](screenshots/02-private-dns-zone-missing-record-set.png)



4\. Created the missing DNS record set using the Private Endpoint FQDN and its private IP address.



!\[Private DNS record creation](screenshots/03-private-dns-record-set-creation.png)



5\. Retested DNS resolution → Successful. However, HTTPS connectivity was still failing.



!\[DNS resolved but HTTPS still failing](screenshots/04-dns-resolved-but-https-still-failing.png)



6\. Used Network Watcher (IP flow verify) → Identified an NSG rule blocking outbound HTTPS traffic (TCP/443).



!\[Network Watcher IP flow verify](screenshots/05-network-watcher-ip-flow-verify-nsg-block.png)



\## Root Cause



Two independent configuration issues affected connectivity:



\- The Private DNS Zone was missing the DNS record required to resolve the Private Endpoint FQDN.

\- An NSG rule was blocking outbound HTTPS traffic (TCP/443).



\## Solution



1\. Created the missing DNS record set in the Private DNS Zone, pointing to the Private Endpoint's private IP address.

2\. Updated the NSG outbound rules to allow the required HTTPS traffic (TCP/443).

3\. Retested DNS resolution using `nslookup` → Successful.

4\. Retested connectivity using `curl -i` with the SAS URL → Successful.

5\. Confirmed that the VM could retrieve and read `Report.txt` from the Storage Account blob container.



!\[Successful DNS resolution and blob access](screenshots/06-successful-dns-resolution-and-blob-access.png)



\## Prevention



\- Verify Private DNS Zone record sets when deploying new Private Endpoints.

\- Review NSG outbound rules to ensure required HTTPS connectivity is allowed.

\- Use Network Watcher IP flow verify to investigate traffic filtering issues.

\- Include DNS resolution and HTTPS connectivity tests in Private Endpoint deployment validation.
