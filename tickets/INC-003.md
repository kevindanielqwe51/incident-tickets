\# Ticket 03: Azure VM Access Denied Due to Missing RBAC Group Membership



\*\*Area:\*\* Identity \& Access Management (IAM)



\*\*Services:\*\* Azure Virtual Machines, Azure RBAC, Microsoft Entra ID, Resource Groups



\---



\## Symptom



Juan reported that he could no longer view or access the Virtual Machines in the Azure Portal, despite previously having access to the resources required for his daily activities.



!\[User VM Access Denied](screenshots/01-user-vm-access-denied.png)



\## Diagnosis



1\. Reviewed the user's access requirements → Juan required the Virtual Machine Contributor role.

2\. Inspected the Resource Group IAM configuration → Identified an Entra ID security group named Administrators with the Virtual Machine Contributor role assigned.

3\. Reviewed the group's membership → Confirmed that Juan was not a member of the Administrators group.

4\. Identified the missing group membership as the reason for the access issue.



!\[Resource Group RBAC Role Assignment](screenshots/02-resource-group-rbac-role-assignment.png)



\## Root Cause



Juan was missing from the Administrators Microsoft Entra ID group, which had the Virtual Machine Contributor role assigned at the Resource Group scope.



\## Solution



1\. Added Juan to the Administrators Microsoft Entra ID group.

2\. Allowed time for the updated group membership and permissions to take effect.

3\. Signed in again using Juan's account.

4\. Verified that Juan could successfully view and manage the required Virtual Machine.

\### Access Validation

\## Prevention



\- Regularly review Microsoft Entra ID group memberships.

\- Implement periodic Azure RBAC access reviews.

\- Follow the principle of least privilege when assigning permissions.

\- Document group ownership and access requirements.

\- Review access changes when employees change roles or responsibilities.
