\# Ticket 03: Expired SAS Token Causing Azure Storage Access Failure



\*\*Area:\*\* Cloud Operations / Security | \*\*Services:\*\* Azure Key Vault, Azure Storage Account, SAS Token



\---



\## Symptom



A user reported that they could no longer access an Azure Storage resource using a previously provided SAS token. The request returned an authentication error indicating that the SAS token was expired or invalid.



!\[SAS Token Authentication Failure](screenshots/01-sas-token-authentication-failure.png)



\## Diagnosis



1\. Accessed Azure Key Vault and inspected the existing secret containing the SAS token.

2\. Reviewed the stored secret and identified that the previous SAS token was no longer valid.

3\. Generated a replacement SAS token with the required permissions and validity period.

4\. Prepared to update the existing Key Vault secret with the new token.



!\[Old SAS Secret in Key Vault](screenshots/02-key-vault-old-sas-secret.png)



\## Root Cause



The previously stored SAS token had expired or become invalid, preventing the user from accessing the Azure Storage resource.



\## Resolution



1\. Generated a new SAS token with the appropriate permissions and expiration period.

2\. Updated the existing secret in Azure Key Vault with the replacement SAS token.

3\. Retrieved the updated secret to verify the new value.

4\. Tested access to the Azure Storage resource using the new SAS token.

5\. Confirmed that access was successfully restored.



!\[SAS Secret Version Update](screenshots/03-key-vault-sas-secret-update.png)



\## Validation



Successfully accessed the Azure Storage resource using the newly generated SAS token.



!\[Azure Storage Access Restored](screenshots/04-azure-storage-access-restored.png)



\## Prevention



\- Monitor SAS token expiration dates.

\- Establish a periodic SAS token rotation process.

\- Store sensitive credentials securely in Azure Key Vault.

\- Apply the principle of least privilege when generating SAS tokens.

\- Review previous secret versions and disable outdated versions when appropriate.



\*\*Security Improvement Note:\*\* During the secret update, I noticed that the previous secret version remained enabled. This was identified as an additional improvement opportunity. Disabling or retiring outdated secret versions can help maintain better secret version management. However, disabling a Key Vault secret version does not automatically revoke an already issued SAS token.
